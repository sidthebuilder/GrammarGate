Inference-Time Defense for Constrained Decoding

Safety gating that checks logits before the grammar mask

Structured output engines enforce schemas and code grammars by masking disallowed tokens to −∞. Attacks like EnumAttack, CodeSpear, and DictAttack use that mask to silence a model's refusal tokens, forcing aligned models to comply.

GrammarGate checks raw logits before the bitmask is applied and monitors rolling prefixes mid-generation. On Qwen2.5-3B-Instruct with XGrammar, it caught 30 of 30 tested smoke attacks without changing model weights.

Section 01 · Vulnerability Mechanism

The Refusal Extinction Vulnerability

Constrained decoding algorithms operate downstream of model forward passes. When an aligned model wants to decline a harmful request, it distributes probability mass over refusal tokens ("I cannot", "Sorry"). Standard engines apply hard bitmasking:

LOGIT-LEVEL BITMASKING FORMULATION:
ztpost[i] = ztpre[i]   if valid_mask[i]   else   −∞
When an adversary constrains output to single-option enums (EnumAttack) or programming grammar syntax (CodeSpear), refusal tokens have valid_mask[i] == 0. Post-mask softmax renormalizes over the remaining tokens, mathematically forcing the model to emit the exploit payload even when pre-mask refusal probability exceeded 99%.
Section 02 · Defense In Depth

The Three-Plane Defense Architecture

GrammarGate inspects unnormalized logits before −∞ bitmasking occurs, enforcing a pre-mask inspection boundary across three coordinated layers.

killed_mass = 1.0 − ∑i ∈ valid Ppre(i)   |   refusal_suppression = ∑i ∈ refusal \ valid Ppre(i)

Section 04 · Scientific Transparency

Honest Limitations & Failure Modes

In keeping with scientific integrity, we transparently document the boundary conditions and open failure modes observed during empirical evaluation.

1. Small Sample Smoke Test (N=10)
The 40-task benchmark serves as a local hardware validation harness. Establishing asymptotic true positive and false positive rates requires scaling to N ≥ 1,000 across diverse model architectures (Llama, Mistral, Gemma).
2. Heuristic Layer 3 Monitoring
Layer 3 currently uses a deterministic regex pattern scanner to inspect materialized dictionary payloads. For enterprise natural-language outputs, Layer 3 must be backed by a distilled 0.5B token-classifier safety judge.
3. Low-Refusal Stealth Decoupling
If an attacker phrases a prompt such that baseline refusal probability is near zero and uses a loose grammar (killed_mass < 0.98), logit thresholding alone cannot distinguish malicious intent without semantic monitoring.
4. Mid-Generation Trips on Raw Python CFGs (20% FPR)
Under the 0.01 threshold override (vs. 0.15 default), benign_py_3 (10 tokens) and benign_py_5 (16 tokens) tripped L2 after emitting valid Python code. Allowing optional prose/fence wrappers via wrap_ebnf_with_preamble in grammargate/preamble_utils.py mitigates un-fenced prose suppression.

cargo build --release --manifest-path grammargate_core/Cargo.toml
